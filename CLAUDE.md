Context for working on this repo. The owner (Görkem) writes in Turkish; answer in Turkish unless he writes in English. The UI and all user-facing text are Turkish.

## What this is

A single-file, fully offline web app (`index.html`) that analyzes Turkish credit-card statements (PDF, including password-protected) and bank exports (xlsx/xls/csv). No build step, no server, no network calls.

**Non-negotiable privacy rules** (the whole reason the tool exists — the owner didn't want to upload statements anywhere):
- Never add network requests, analytics, CDNs or external fonts. Libraries are embedded. **The one exception (owner's decision):** exchange rates for the budget tab are fetched from one fixed file of fawazahmed0/currency-api, `RATE_URLS` tried in order: `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.json` first, then the same file at `https://latest.currency-api.pages.dev/v1/currencies/usd.json` (pages.dev timed out on the owner's network, so the owner chose jsDelivr) — only while the Birikim tab is open and a non-TL asset exists (once per opened data file, plus the "Kurları güncelle" button); the fallback is requested only when the first fails; GET with `credentials:"omit"`, `referrerPolicy:"no-referrer"`, nothing from the user ever added to the request. The services see the IP and the time. Never add another host or path, or put data in this request.
- Never use localStorage/sessionStorage/IndexedDB. Data lives only in the user's `harcama-verisi.json`. The one exception is the service worker's Cache Storage, which holds only the app's own files (`APP_FILES` in `sw.js`), never user data.
- The `Content-Security-Policy` meta tag at the top of `index.html` is the network lock (`default-src 'none'`, `connect-src` = exactly the two rate **file URLs** above). They are full paths on purpose: CSP path matching keeps every other path on cdn.jsdelivr.net (any npm package, public download stats — an exfiltration channel) and on pages.dev closed; never shorten them to a host, folder or `*`. Limits, honestly: CSP path matching ignores the query string, and after a redirect only the host is checked. Don't loosen it further; `'unsafe-eval'` + `blob:` are only for unpacking the embedded libs (SheetJS, PDF.js, Preact/htm) and the PDF.js worker.
- Never commit real statements or data files. `.gitignore` blocks them. Test fixtures must be synthetic.
- PDF passwords live only in memory (`lastPw`) for the page session.

## PWA (install on phone, works offline)

- `manifest.webmanifest` + `icons/` (donut in the `PAL` colors, generated, inside the maskable safe zone) + `sw.js`. `index.html` registers `sw.js` only over http(s) (not `file://`, so tests and opening the file directly are unchanged).
- `sw.js` caches `APP_FILES` per scope (cache name includes the scope, so `/onizleme/<branch>/` previews don't clash with the root). The page itself is network-first with a 3 s timeout, falling back to the cached copy: online opens get the latest `main`, offline opens the last one. Other files cache-first. Requests outside `APP_FILES` (e.g. `/onizleme/` list) pass through untouched.
- Adding a new app file: add it to `APP_FILES` in `sw.js` and to the `publish()` list in `pages.yml`.

### Storage
- Desktop (Chrome/Edge): `showDirectoryPicker` → writes `harcama-verisi.json` (+ `.onceki.json` backup) in the chosen folder.
- Phone/other (`MOBILE = !showDirectoryPicker`): open the JSON via file input, "Kaydet" downloads it.
- `snapshot()` / `applyData()` define the file schema: `history, statements, overrides, excluded, viewMode, rules, lastMap` plus the optional `notes` (`{txId: "text #tag"}`), `dismissed` (hidden anomaly-warning ids), `budget` (`{items, assets, rates}`, see "Birikim ve bütçe"; `normBudget` sanitizes it, old files get an empty one) and `removedDefaults` (default rules the user deleted: `"Kategori|ANAHTAR"` or `"Kategori|*"`, so the load-time default merge doesn't re-add them — `applyData` merges `defaultsText()`, not `DEFAULT_RULES`); transactions may carry `card` (last 4 digits) and `statements[stmt].card`. `applyData` also runs `migrate()` + `expandInstallments()`. Keep old files loadable.

### PDF parsing (`pdfToRows` → `linesToRows`)
- Text items grouped into lines by y; items joined with a space only when there is a real x-gap (handles letter-by-letter PDFs).
- Rotated text and vertically stacked single letters (margin document info) are dropped before line grouping. A stack is only "vertical text" if it has ≥4 *distinct* characters; narrow table columns with few values (a `B`/`A` debit/credit marker, a `-` column) are kept.
- `dropNonTxSections`: skips points sections (Worldpuan/ParafPara/Chip-Para/Bonus details) until the next transaction table header.
- Each date starts a transaction; text until the next date = description + amounts. Dates: `26.07.2026`, `26/07/26`, `2026-07-26`, `26 Temmuz 2026` (month names in any case), year-less at line start. A line starting `2/3 Taksit` is installment info, not a year-less date. Year-less rows carry `row.ny`; once the cut-off date is trusted, `settleRowsByCutoff` resolves their year so the date is ≤ cut-off+3 days (a December purchase on a January statement is the previous year) and drops rows dated more than 2 days **after** the cut-off (due-date/information sentences such as "… 05.09.2026 tarihine kadar 300,00 TL ödeyiniz").
- Amounts: Turkish format `1.234,56`. Numbers after the amount without `,dd` are bonus points (ignored), e.g. `500,00 10`. **Foreign currency**: an amount directly followed/preceded by a currency code or symbol (`25,00 USD`, `EUR 40,00`; a code belongs to the amount before it first) is not the TL amount; the TL amount is taken (the one equal to foreign × rate if a rate column exists, else the first TL amount) and the foreign amount goes into the note (`Döviz: 25,00 USD`). A trailing lone `A`/`(A)`/`ALACAK`/`CR` after the amount marks a credit (negative → refund/payment); `B` (debit) changes nothing. Times (`14:35`), currency codes and installment markers are stripped from the description so the same merchant is one merchant.
- Installments: `4.964,93 TL'lik işlemin 2 / 3 taksidi` (same or next line), a bare `2/6` column, `(2/3)`, or `2/3 Taksit` on the next line. When a row has several amounts, the one where `amount × count ≈ total` is the installment (e.g. `1.624,27 6.497,08 / 4` → 1.624,27; the second is remaining balance / remaining count).
- Sign: on card statements purchases are unsigned; `+` amounts are payments/refunds. `PAY_RE` separates payments (kept as `kind:"payment"`, never counted as spending) from refunds (`kind:"refund"`, negative, reduce spending).
- Statement summary: `findStmtDate` (cut-off date: same line, table header with values on the next line by x-column, label-below, "Ekstre Dönemi a - b", spaced letters; a candidate is plausible when ≥60% of the transaction dates fall in [cut-off−60, cut-off+2] days — one stray row can't veto it — so "Son Ödeme Tarihi" is never picked). `findLabeledAmount` for `due` (Dönem Borcu) and `prev` (Önceki Dönem Borcu). Amount x-position is taken from its first digit.

**Known PDF limits** (not handled): an unsigned "ÖDEME TEŞEKKÜRLER" row counts as spending; space-separated thousands (`1 234,56`) are misread; a 2-decimal number inside the description (`TURKCELL 5,00 TL YUKLEME 50,00`) is taken as the amount; "3 TAKSİT" (count only) is not an installment series; a row with only a foreign amount is left in `pdfMissed` (add it by hand via the recon "Ekle").

### Periods, installments, reconciliation
- Grouping is by **statement period**, not calendar month: every transaction from a PDF gets `stmt` (cut-off date); `periodKey(t) = t.stmt ? stmtMonth(t.stmt) : t.date.slice(0,7)`. `stmtMonth`: a cut-off on day 1–5 belongs to the **previous** month (month-end cards drift 31 Jan → 1 Mar → 31 Mar; without this February is empty, March gets two statements and installment estimates from `shiftMonth` land a month late). Never compare statement keys with `.slice(0,7)`; use `stmtMonth`. Banks post late, so a 25 Jul purchase can legitimately be on the 26 Aug statement.
- Installments are billed in the statement month, not the purchase month (banks print the original purchase date on every installment line). `expandInstallments()` rebuilds the whole series every time: real rows from statements, `est:"past"` for missing earlier ones, `est:"future"` for upcoming ones. Estimates are never saved as real and are replaced when the real statement arrives. `sameInst` matches series by description + count + total.
- Re-importing the same statement must not duplicate; it updates `stmt` on existing rows (repairs records saved by older versions).
- `renderRecon`: prev − payments + purchases − refunds must equal the statement's Dönem Borcu; shows the diff and unread lines with an "Ekle" button. This check is the main correctness signal — keep it green.

### Categorization
- Rules are editable text `Kategori: KEY1, KEY2`; `categorize` picks the **longest** matching keyword; keys ≤4 chars match whole words only (so `PET` ≠ `PETROL`, `DIS` ≠ `YURT DISI`). Per-description `overrides` win.
- `mergeRules(base, incoming)` adds missing keywords/categories without removing anything; used for default-rule merge in `applyData` and for category import.
- Sharing between people (each has their own data file): "Kategorileri paylaş" downloads `harcama-kategorileri.json` = `{type:"kategoriler", version, updated, rules, overrides}` — no transactions/amounts. "Kategorileri içe aktar" accepts that file or a full `harcama-verisi.json` (only `rules`/`overrides` are read). `planImport` computes the diff without changing anything (new keywords in existing categories, new categories, new merchant picks, conflicting picks); the user sees it in `#sharePreview` with a checkbox per item (new items ticked, conflicts unticked = keep own) and nothing is saved until "Uygula". `applyImport` applies only the ticked items via `mergeRules`.
- **Rule editor** (`#rulesEd`, `RulesEditor`/`RuleCard`): category cards with keyword chips, add/remove/move keyword, rename/delete category, add category, search, "Kural dene" (`explainCategory`: which keyword wins and why), "Varsayılan kuralları tamamla". The `#rules` textarea (now under "Metin olarak düzenle (gelişmiş)", `#rulesText`) stays the single source of truth: every edit goes through `setRulesList` → `undoable` → `$("rules").value` (keywords are stored via `norm`, i.e. ASCII upper-case like the defaults). Renaming/deleting a category also updates `overrides`, `excluded`, `txView.cat`. Deleting a default keyword/category records it in `removedDefaults`.
- Special categories: `Taksitler` (all installments; sub-category = rule category), `İadeler ve indirimler`, `Diğer` (unmatched).

- **Kural önerisi** (`UnkRow`/`applyUnk`): picking a category for an uncategorized place adds `Category: KEYWORD` via `mergeRules` (editable suggested keyword, checkbox) or falls back to a per-description override.
- **Geri al** (`undoable`, `undo`, `#toast`): wrap user-initiated data changes in `undoable(label, fn)`; it snapshots, runs `fn`, saves, re-renders and shows a 6 s toast; Ctrl/Cmd+Z outside inputs also undoes (one level, memory only). The toast label wraps instead of being cut, and the button never wraps, so it fits a phone screen.
- **Kart ayrımı**: `findCard` reads a masked card number from the PDF text; `cardSel` (`#cardSel`, shown only with ≥2 cards) filters totals, lists, analysis and recon. Limitation: statements are keyed by cut-off date, so two cards with the *same* cut-off date share one statement/recon entry.
- **Yazdır**: `#tbPrint` → `window.print()`; `@media print` switches to a light theme, hides controls/rules/uncategorized, expands scroll areas; `beforeprint`/`afterprint` open and restore the `<details>` folds.
- **Other**: period selector (all time / each statement / custom date range with presets), category include/exclude checkboxes (affects totals, charts, lists), bar or donut chart (top 6 colored, rest folded to gray), "Dönemlere göre" chart, merchant analysis (`renderQuery`, scoped to the selected period; items in every list are clickable via `data-an`), multi-file upload with a per-file result list (`.flist`), category share export/import. "Dönemlere göre", "Kategori trendleri", "Yıllık özet", "Tüm işlemler", "Kategorisi bulunamayanlar" and "Kategori kuralları" are native `<details class="fold">` sections (`#monthsFold`, `#trendFold`, `#yearFold`, `#allFold`, `#unkFold`, `#rulesFold`), closed by default, with counts in the title (`#…Count`); a category import opens `#rulesFold` so the preview is visible; open state is not saved and survives re-render because `render()` only rewrites the tables.

Layout: before any data the page shows the intro, numbered step panels (`#folderPanel`/`#mobilePanel`, `#drop`) and a 3-step guide (`#how`). Once `history` is non-empty `render()` sets `body.has-data`: CSS hides intro/steps/drop and shows the compact `#toolbar` (folder or file name, counts, "+ Ekstre ekle" → `#file`, folder/file switch) and the "🔒 Çevrimdışı" badge; "Geçmişi sil" lives in the `#hist` fold at the bottom. Files can be dropped anywhere on the page (`handleFiles`, same path as `#file`). The total sits in `.hero` with KPI cards from `renderKpis` (all time: per-period average, upcoming installments; statement: reconciliation status, click opens `#recon`; range: daily average; always: largest category). Multi-file results are a `.flist` list, not a table (fits phones). Category rows use grid areas so the percentage drops under the amount at ≤640px. `.hide` is `!important`.

VERBOSE=1 python tests/run_tests.py         # print tracebacks

## Deployment

## Branches and commits

### Branches

For **every** new feature or fix, work on a **new branch**. Before creating it, ask the owner two things and wait for the answers (do not guess, do not reuse a default):
1. **The branch name.**
2. **Which branch to start from.** Do not assume `main`; the owner may want a different base. Offer `main` as the default option.

Rules:
- Never start work on, or push to, a branch the owner has not named in this conversation. Never reuse an old or already-merged branch for new work; if the owner wants the same name again, restart it from the chosen base.
- Never create a pull request or merge unless the owner asks for it. Ask before deleting branches (remote deletion is often blocked in the cloud environment; then tell the owner to use GitHub's "Delete branch").
- Before the first commit, make sure the branch is based on the up-to-date base (`git fetch`), so a PR does not carry unrelated history.

### Commits

Never put session info (Claude session links/IDs, `Claude-Session:` trailers, claude.ai/code URLs) in commit messages, PR titles/bodies, merge commits or comments. The GitHub integration may append a footer with the session link to a PR body automatically; after creating or editing a PR, read the body back and remove it.

Commit messages in Turkish, short subject + body explaining why.
